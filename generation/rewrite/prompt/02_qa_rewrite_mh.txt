You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, generate a question that requires integrating multiple independent information sources (evidence hops) to answer. Target task type: **MH (Multi-Hop)**.

Generate exactly 5 questions using the question session ID and its session summary to construct unambiguous references.

## SUBTYPES

| Subtype | Definition | Construction | Difficulty Requirement | Common Errors |
|---------|-----------|--------------|----------------------|---------------|
| **Conditional filtering** | Filter candidates based on user-defined conditions | Build compound conditions (AND/OR/NOT) with at least one near-miss candidate that barely passes or fails. Include at least one exception rule. | Near-miss + exception rule mandatory | ✗ Single-threshold binary check ("Is X > 9?"). ✗ Binary conditions without interaction |
| **Counting/Aggregation** | Count or aggregate across sources with user-defined units | Multimodal provides raw counts or categories; text hops define user-specific rules that change "what counts as one unit" (e.g., exclusions, multipliers, grouping rules). Simple "count all X" is forbidden. | User-defined counting rule mandatory | ✗ Small-number multiplication (4×3=12). ✗ Obvious category membership ("pigeons are urban wildlife"). ✗ Raw count directly from multimodal without rule application |
| **Comparison** | Compare objects/events based on user-defined dimensions | Multimodal provides raw attribute values for ≥2 objects; text hops define the user's custom formula/weighting to derive a comparison metric. Direct attribute comparison is forbidden. | Derived dimension mandatory | ✗ Direct attribute comparison ("which is taller?"). ✗ Single-step lookup. ✗ Standard formulas (domain knowledge alone suffices) |

## CORE PRINCIPLE

**Multimodal content provides simple perceptual facts (counts, colors, positions, categories, sounds). Difficulty comes from text hops defining user-specific rules that make these simple facts non-straightforward to reason about.** Text hops provide general rules established before the multimodal content — they never reference the specific multimodal content.

## RULES

### Question Design

**Q1. Strong necessity test**: Remove any hop → answer becomes undeterminable or **different**. If removing a hop merely removes context but the answer stays the same, redesign.

**Q2. Distractor complexity**: Every question must include at least one plausible wrong answer resulting from a reasonable but incomplete reasoning path — not just from skipping a hop, but from applying a related-but-wrong rule. Identify this in reasoning.

**Q3. Natural conditions**: User-defined rules/thresholds/criteria must feel realistic for the persona.

**Q4. Perceptibility**: Multimodal evidence must be directly perceivable.
- ✓ Allowed: counts, presence/absence, relative comparisons, colors, actions, sequences, instrument types, emotional tone, general tempo (fast/slow)
- ✗ Forbidden: BPM, frame rate, resolution, exact duration in seconds, decibel levels, Hz

**Q5. Surface contradiction (≥2 of 5)**: At least 2 questions must contain hops that appear contradictory on the surface but are reconcilable via scope/context distinction. Reasoning must show the wrong answer from failing to distinguish scope.

**Q6. Common-sense resistance**: The answer must NOT be derivable from general domain knowledge combined with the multimodal perception alone. The user-defined rules in text hops must be essential — without them, the answer is indeterminate or different.

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). Each question must have at least one multimodal hop and at least 2 text hops with independent information.

**E2. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type`, `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E3. Temporal safety**: All text hops must come from sessions with timestamps ≤ the multimodal hop's session timestamp. When multiple multimodal hops exist, check each independently. This prevents information leakage.
- ✓ text S3 (Jan 3) → text S4 (Jan 4) → image S5 (Jan 5)
- ✓ text S3 (Jan 3) → video S5 (Jan 5) → text S4 (Jan 4) [S4 ≤ S5 ✓]
- ✗ image S5 → text S7 discussing what S5's image shows

**E4. Multimodal irreplaceability**: Text hops provide rules/criteria/context only — never perceptual facts. The perceptual judgment must come from the multimodal content. If a text hop states "track has picking and strumming" when that is the key multimodal fact, redesign.

**E5. Hop necessity**: Every hop must be load-bearing. In reasoning, state: "If hop N removed → [specific wrong answer]."

**E6. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. At most **1 text hop per question** may be a direct rule statement (`[explicit]`); all others must embed info as incidental remarks (`[incidental]`). Tag each in reasoning.

**E7. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD). Only use sessions listed in Available Sessions.

**E8. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments to make it 4" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain (e.g., food photo for a gallery curator), abstract to domain-appropriate properties (color tone, texture, reflectivity) rather than referencing the source domain directly (seasoning, herbs).

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the SFX sampler I uploaded during the comedy scoring session"
- ✗ "the audio with three sound effects"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.

## SELF-CHECK CHECKLIST

Before generating output, verify:

1. **Count**: Exactly 5 questions.
2. **Hops**: ≥4 per question (recommended 6). Each multimodal file is a separate hop. Hop counts vary across questions.
3. **Subtypes**: ≥2 different subtypes across 5 questions.
4. **Temporal safety**: Every text hop's session timestamp ≤ each multimodal hop's session timestamp.
5. **Multimodal irreplaceability**: Perceptual facts come only from multimodal content. No text hop restates them.
6. **Necessity**: Each hop removal → specific wrong answer stated in reasoning.
7. **Difficulty**: Every question has a boundary case / ambiguous membership / derived dimension (per subtype).
8. **Distractor**: Every question has a plausible wrong answer from incomplete reasoning.
9. **Surface contradiction**: ≥2 of 5 questions have apparently contradictory hops reconcilable via scope.
10. **Naturalism**: ≤1 `[explicit]` text hop per question. Others `[incidental]`.
11. **References**: Event-context only. Unambiguous across sessions.
12. **short_answer**: Contains only the answer — no qualifiers or reasoning.
13. **Independent multimodal hops**: Each multimodal file is a separate hop with its own `mm_id` (string). No combined types like `image+audio`.
14. **Common-sense resistance**: Answer requires user-defined rules from text hops, not derivable from domain knowledge + multimodal alone.
15. **Evidence quality**: Each text hop is self-contained (no missing subjects) and domain-coherent (no out-of-place terminology for the persona).
