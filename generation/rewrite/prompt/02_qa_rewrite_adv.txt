You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, create statements for the model to judge whether each conflicts with dialogue memory. Target task type: **ADV (Adversarial - False Premise)**.

Generate exactly 5 questions. Format: "Determine whether the following statement conflicts with the dialogue memory: [statement]"

## SUBTYPES

| Subtype | Definition | Construction | Common Errors |
|---------|-----------|--------------|---------------|
| **Fabricated fact** | Claims something that doesn't exist in content | Change ONE perceptual detail to a near-miss alternative within the same fine-grained subcategory (e.g., 1→2 objects, left→right position) | ✗ Cross-category swap (piano→drums). ✗ Order-of-magnitude change (3→30). ✗ Fabricated entity absent from all sessions |
| **Misattribution** | Attributes to the wrong entity | Swap ONE perceptual property between two entities that both appear AND belong to the same category. Cascade all downstream claims consistently from this single root swap. See Example 2 | ✗ Swap between different categories (chef↔audience). ✗ Entities with obviously different descriptions |
| **Temporal displacement** | Gets time/order wrong | Swap two adjacent steps or events as perceived in the multimodal content | ✗ Large time jumps. ✗ Reversing entire sequences |
| **Version conflict** | Correct under old rule, wrong under current | Statement applies outdated criteria while implying current compliance. The factual basis for applying the rule must come from multimodal perception. See Example 2 | ✗ Using version conflict for ≥2 of 5 questions |

## RULES

### Statement Design

**S1. Minimal perturbation**: The false claim must be a near-miss — same fine-grained subcategory, differing by one small perceptual detail. Test: a knowledgeable person without the multimodal evidence should find the false statement plausible.

**S2. Claim density (Yes statements)**: ≥4 independently verifiable claims, exactly one false. Correct claims must be potentially confusable details (not obviously correct background). At least one correct claim must be **counter-intuitive** — it must contradict a "normal expectation" established by at least one text hop, yet be confirmed correct by evidence. Example: a text hop says electric guitars in the archive typically use heavy distortion → statement claims clean tone → multimodal content confirms clean tone.
- ✗ Forbidden: padding with trivially correct claims like "both are in a kitchen"

**S3. Counter-intuitive design (No statements)**: ≥4 independently verifiable claims, all correct. At least one claim must contradict a "normal expectation" established by at least one text hop, yet be confirmed correct by evidence.

**S4. Perceptibility**: Multimodal evidence must be directly perceivable.
- ✓ Allowed: counts, presence/absence, relative comparisons, colors, actions, sequences, instrument types, emotional tone, spatial layout, motion direction
- ✗ Forbidden: exact durations in seconds, BPM, frame rates, resolution, decibel levels, Hz

**S5. Perceptual anchor by modality**: The false claim (for Yes) or the key counter-intuitive claim (for No) must target a perceptual dimension native to the modality. Text hops provide context/motivation only — never the perceptual fact itself.

| Modality | Anchorable dimensions |
|----------|----------------------|
| **Image** | Object count, spatial layout (left/right/front/back), color, presence/absence, relative size, text/signage content, material/texture |
| **Video** | Action sequence/order, motion direction, appearance/disappearance timing, scene transitions, simultaneous events, spatial trajectory |
| **Audio (music)** | Instrument type/count, vocal presence/absence, melodic mood (upbeat/somber), structural order (intro/verse/chorus/outro), tempo feel (fast/slow) |
| **Audio (speech)** | Speaker count, language, emotional tone, keyword-level content, turn order, interruptions |
| **Audio (sound)** | Sound source type/count, co-occurrence, temporal order, presence/absence of specific sounds |

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). Vary counts across the 5 questions.

**E2. Temporal safety**: All text hops must come from sessions with timestamps ≤ the multimodal hop's session timestamp. When multiple multimodal hops exist, check each independently. This prevents information leakage by ensuring no text hop can retroactively describe multimodal content.
- ✓ text S3 (Jan 3) → text S3 (Jan 3) → image S5 (Jan 5)
- ✓ text S4 (Jan 4) → audio S5 (Jan 5) → text S3 (Jan 3) [text S3 ≤ S5 ✓]
- ✗ text S3 → image S5 → text S7 discussing what S5's image shows

**E3. Multimodal irreplaceability (text-only shortcut test)**: The false claim's truth value must be determinable **only** through multimodal perception. No text hop — individually or collectively — may contain information sufficient to judge whether the false claim is true or false. **Test: mask all multimodal hops. If the model can still determine the false claim's truth value using only text hops → redesign.**

For version conflict: the rule comes from text, but whether the rule is triggered must depend on a perceptual fact from the multimodal content (e.g., text says "no vocals allowed"; only audio reveals vocals are present).

**E4. Hop necessity**: Every hop must be load-bearing. In reasoning, state: "If hop N removed → [specific wrong outcome]."

**E5. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. At most **1 text hop per question** may be a direct rule statement (`[explicit]`); all others must embed info as incidental remarks during other discussions (`[incidental]`). Tag each in reasoning.

**E6. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD matching the session's date). Only use sessions listed in Available Sessions.

**E7. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type` (e.g., `"image"`, `"audio"`), `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E8. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments to make it 4" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain, abstract to domain-appropriate properties rather than referencing the source domain directly.
- **No perceptual leakage**: Text hops must never describe perceptual facts from the multimodal content (counts, colors, spatial relations, sounds heard, actions seen). They may only provide context, motivation, rules, or criteria.

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the desk photo I shared during the workspace audit"
- ✗ "the photo showing a keyboard and succulent"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions, using `question_session_id` and its session summary.

## SELF-CHECK CHECKLIST

Before generating output, verify:

1. **Distribution**: Exactly 5 questions. 3–4 Yes + 1–2 No. ≥3 different subtypes. Version conflict ≤1. Fabricated fact ≤2. Misattribution ≥1.
2. **Statement quality (Yes)**: ≥4 verifiable claims, exactly 1 false (near-miss), ≥1 counter-intuitive correct claim.
3. **Statement quality (No)**: ≥4 verifiable claims, all correct. ≥1 counter-intuitive correct claim.
4. **Evidence chain**: ≥4 hops per question (recommended 6). Hop counts vary across the 5 questions.
5. **Temporal safety**: Every text hop's session timestamp ≤ each multimodal hop's session timestamp.
6. **Multimodal irreplaceability (text-only shortcut test)**: Mask all multimodal hops. Can the model still determine the false claim's truth value using only text hops? If yes → redesign. For No answers: can the key counter-intuitive claim be verified without the multimodal content? If yes → redesign.
7. **Naturalism**: ≤1 `[explicit]` text hop per question. Others are `[incidental]`.
8. **References**: Event-context only. No perceptual descriptions. Unambiguous across sessions.
9. **No single subtype across all 5 questions**.
10. **Independent multimodal hops**: Each multimodal file is a separate hop with its own `mm_id` (string). No combined types like `image+audio`.
11. **Evidence quality**: Each text hop is self-contained (no missing subjects), domain-coherent, and contains **no perceptual facts from the multimodal content** (no counts, colors, sounds, actions observed in the media).
12. **mm_id consistency**: Every multimodal hop's `mm_id` in `evidence_chain` exactly matches the corresponding `mm_id` from the input caption.
