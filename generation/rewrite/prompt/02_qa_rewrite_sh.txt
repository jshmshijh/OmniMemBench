You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, generate a natural, persona-appropriate question that requires **precise, fine-grained understanding** of the multimodal content and can be answered directly from it (single-hop). Target task type: **SH (Single-Hop)**.

Generate exactly 5 questions using the question session ID and its session summary to construct unambiguous references.

## DIFFICULTY PATTERNS

Every question must satisfy at least one of these patterns:

| Pattern | Definition | Construction | Common Errors |
|---------|-----------|--------------|---------------|
| **Spatial/relational disambiguation** | Multiple similar elements; answer depends on position or adjacency | Ask about an attribute of one element, where another similar element nearby has a different value for that attribute | ✗ Only one instance of the target category exists |
| **Counter-default detail** | Correct answer contradicts a strong default assumption | Ask about a detail where the content violates expectations for its category | ✗ Answer aligns with the obvious assumption |
| **Cross-element attribute transfer** | Similar entities share some attributes but differ in the target attribute | Ask about the differing attribute, requiring correct binding to the right entity | ✗ Entities are from different categories (not actually confusable) |
| **Peripheral precision** | Answer is a specific peripheral detail, not the main subject | Ask about a setup/background detail when a more salient but incorrect candidate exists | ✗ Target detail is the most prominent element |

## RULES

### Question Design

**Q1. Confusable alternatives (mandatory)**: The multimodal content must contain at least one other element from the **same semantic category** that could plausibly be confused with the correct answer. The confusable and correct answer must **share ≥2 attributes** and differ only in the target attribute. If only one instance exists, the question must target a counter-default detail.

**Q2. Answer non-suggestiveness**: Question wording must not leak or hint at the answer. For Yes/No questions, both answers must be equally plausible from wording alone. Test: read only the question — if you feel >60% pulled toward one answer, reword.
- ✗ "rapid enough to qualify" (suggests Yes)
- ✗ "too cluttered for" (suggests Yes)

**Q3. Answer type mix**: At most 2 of 5 questions may be Yes/No. Others must require specific short answers (name, color, count, position, etc.).

**Q4. Perceptibility**: Evidence must be directly perceivable.
- ✓ Allowed: counts, presence/absence, relative comparisons, colors, actions, emotional tone, categories
- ✗ Forbidden: BPM, frame rate, resolution, exact duration in seconds, decibel levels

**Q5. Preserve answer validity**: The answer must be unambiguously derivable from the actual multimodal content. Difficulty must not compromise correctness.

**Q6. Common-sense resistance**: The answer must NOT be guessable from the scene category or general world knowledge alone. If knowing "this is a café" or "this is a chemistry lab" is enough to guess the answer, redesign.
- ✗ "Is there an espresso machine in the café?" (common sense: cafés have espresso machines)
- ✗ "Are there beakers in the lab photo?" (common sense: labs have beakers)
- ✓ "What color liquid is in the beaker closest to the student's hand?" (requires actual perception)

### Anti-Patterns (FORBIDDEN)

- **Pure direct retrieval**: "What animal is shown?" when only one animal exists
- **Binary with distant options**: "Piano or drum?" — too easy to distinguish
- **Gist-answerable**: "Does this scene take place outdoors?" — answerable from vague impression
- **Common-sense solvable**: Answer derivable from scene category or general knowledge without perceiving the actual content
- **Weak confusables**: Elements merely coexist but share no attributes (red apple vs. green book)

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the lab bench photo from our equipment audit"
- ✗ "the photo showing beakers with colored liquids"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.
