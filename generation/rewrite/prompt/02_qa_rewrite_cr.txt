You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, generate a question that requires **inferring** information by integrating multiple hops — the answer should NOT be explicitly stated in any single hop, and should NOT be derivable by simple one-step attribute matching. Target task type: **CR (Causal Reasoning)**.

Generate exactly 5 questions. All questions must be answerable with Yes/No (or a short evaluative answer like "Better/Worse").

## SUBTYPES

| Subtype | Definition | Question Pattern | Common Errors |
|---------|-----------|-----------------|---------------|
| **Cause/Motivation inference** | Infer why something happened or why user made a choice | "Is the reason I did X related to Y?", "Did I choose X because of Y?" | ✗ Asking about the obvious cause. ✗ Single-attribute matching |
| **Effect/Outcome inference** | Infer the result or impact of something on the user | "Would X cause Y for me?", "Would replicating X make my situation better or worse?" | ✗ Effect obvious from common sense. ✗ No persona-specific threshold |
| **Judgment/Evaluation inference** | Infer user's opinion, preference match, or multi-criteria evaluation | "Does X meet my criteria for Y?", "Would X qualify for both my A and B collections?" | ✗ All dimensions pass/fail uniformly. ✗ Criteria guessable from domain knowledge |
| **Chain reasoning** | Link information across sources through a chain where at least one intermediate conclusion is derived, not stated in any hop | "What is the correct X for Y?", "Which category does Z fall into?" | ✗ Every intermediate value is explicitly stated in some hop (that's MH, not CR). ✗ Synonym-based linking |

## WHAT COUNTS AS CAUSAL REASONING

**NOT CR (single-step matching — FORBIDDEN):**
- [text] User requires SI units → [image] Diagram uses imperial → "Does this meet the standard?" One-step: imperial ≠ SI → No.

**NOT CR (domain-knowledge fillable — FORBIDDEN):**
- [text] User wants "warm" sound → [audio] Bass-heavy audio → "Does this match?" The mapping "bass-heavy = warm" is common audio knowledge; no persona-specific step needed.

**NOT CR (all intermediates explicitly stated — that's MH):**
- [text] "X means death" → [text] "death = critical" → [text] "critical = RA-3F" → [image] shows X. Every intermediate is directly stated. This is multi-hop lookup, not causal reasoning.

**IS CR (persona-specific intermediate):**
- [text] User's "stress test" rule: ≥3 unit conversions required → [image] Circuit with mV, µA, kΩ → [text] Final answers must be in SI base units → "Does this qualify as a stress test?" Model must: identify units from image → determine which need conversion → count conversions → compare to persona-specific threshold. The intermediate "3 conversions needed" is derived, not stated.

**IS CR (causal chain with hidden mechanism):**
- [text] User gets migraines from prolonged high-contrast flickering → [video] Rapidly alternating B&W slides → [text] Meeting is 3 hours → "Should I be concerned?" Model must chain: visual pattern → matches trigger → duration = prolonged → health risk.

**IS CR (chain with derived intermediate):**
- [text] User classifies outcomes by severity tiers → [image] Chart shows symbol X for a case → [text] Severity tiers map to review tracks. But the intermediate "what severity tier does X correspond to?" requires interpreting the symbol AND applying user's non-standard tier boundaries — the tier assignment itself is derived, not directly stated.

## RULES

### Question Design

**Q1. Inference, not matching**: The answer must require combining information through a non-trivial reasoning step. "Hop says X, content shows not-X, therefore No" is NOT CR. There must be at least one **implicit intermediate conclusion** — a fact derived, not directly stated in any hop.

**Q2. Persona-specific intermediate**: The implicit intermediate must depend on a persona-specific definition, threshold, or mapping. If domain knowledge alone suffices, redesign.

**Q3. Multi-dimensional judgment**: For Judgment/Evaluation questions, criteria must involve ≥2 independent dimensions with a **split verdict** (some pass, some fail). At least one dimension's result must be counter-intuitive.

**Q4. Multimodal as reasoning bottleneck**: If you remove all multimodal hops and keep only text, the answer must become indeterminate. Raw perceptual facts from multimodal must be mapped to persona-specific concepts before entering the reasoning chain.

**Q5. Perceptibility**: Multimodal evidence must be directly perceivable.
- ✓ Allowed: counts, presence/absence, relative comparisons, colors, actions, emotional tone
- ✗ Forbidden: exact duration in seconds, BPM, frame rate, resolution, decibel levels

**Q6. Chain reasoning distinction**: For Chain reasoning questions, at least one intermediate value in the chain must be **derived through reasoning**, not directly stated in any hop. If every intermediate can be found verbatim in some hop, it belongs in MH, not CR.

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). Vary counts across the 5 questions.

**E2. Temporal safety**: All text hops must come from sessions with timestamps ≤ the multimodal hop's session timestamp. When multiple multimodal hops exist, check each independently.
- ✓ text S4 → text S5 → image S8
- ✗ text S4 → image S5 → text S7 describing what S5's image shows

**E3. Multimodal irreplaceability**: Text hops provide rules/criteria/context; multimodal hops provide perceptual facts. No text hop may restate a perceptual fact from the multimodal content.

**E4. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. At most **1 text hop per question** may be a direct rule statement (`[explicit]`); all others must embed info as incidental remarks (`[incidental]`). Tag each in reasoning.

**E5. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD). Only use sessions listed in Available Sessions.

**E6. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type`, `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E7. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments to make it 4" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain (e.g., food photo for a gallery curator), abstract to domain-appropriate properties (color tone, texture, reflectivity) rather than referencing the source domain directly (seasoning, herbs).

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the garden photo from the portfolio review session"
- ✗ "the photo showing a red bridge and koi pond"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.

14. **Chain reasoning distinction**: For Chain reasoning questions, verify at least one intermediate value is not explicitly stated in any hop.
