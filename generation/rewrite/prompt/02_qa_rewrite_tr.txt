You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, generate a question that requires reasoning about temporal relationships between events from different hops. Target task type: **TR (Temporal Reasoning)**.

Generate exactly 5 questions using the question session ID and its session summary to construct unambiguous references.

## SUBTYPES

| Subtype | Answer Type | Construction | Difficulty Requirement | Common Errors |
|---------|------------|--------------|----------------------|---------------|
| **Ordering** | "before/after" or "yes/no" | Compare two event dates, both derived from indirect expressions. Gap between events must be ≤2 days. | ≥2 indirect anchors, gap ≤2 days, ≥4 hops | ✗ Events months/weeks apart. ✗ Directly stated dates |
| **Duration/Interval** | "X days" (non-round) | Calculate span between two events. Both endpoints must require indirect calculation. Chain ≥2 calculations. | Non-round answer (avoid 7,14,21,30), chained calc, ≥4 hops | ✗ Round number answers. ✗ Single-step calculation |
| **Recency/Extrema** | Date or event description | Find earliest/latest event meeting a condition. Include near-miss distractors within 1-2 days of boundary. | ≥1 near-miss distractor, conditional filter, ≥4 hops | ✗ Only 2 candidates. ✗ No near-miss |
| **Temporal Relationship** | "yes/no", "overlapped", "during" | Determine if event falls within a time span. The tested point must be within 1 day of a span edge. | Boundary ≤1 day from edge, span endpoints from different hops, ≥4 hops | ✗ Wide margins. ✗ Span from single hop |

## RULES

### Question Design

**Q1. Temporal reasoning is core**: The answer must depend on comparing, ordering, or calculating time relationships — not just retrieving content.

**Q2. Minimum TWO indirect time anchors**: Every question must include at least two time points requiring calculation from relative expressions. Directly stated dates ("on January 15th") count as zero indirect anchors.
- ✓ "my course starts eleven days from now" (requires: session date + 11)
- ✓ "I submitted it nine days ago" (requires: session date − 9)
- ✗ "the event is on January 15th" (direct, too easy)

**Q3. Multi-step chains**: The answer must require chaining 2-3 calculations, not a single comparison.

**Q4. Session date vs. event date**: The `timestamp` field is always the **session date** (when the user mentioned it). When the actual event occurred at a different time, describe the inferred event date in the evidence text. Temporal reasoning uses **inferred event dates**, not session dates.
- Session on Jan 10, user says "I adopted Luna last week" → event date ~Jan 3
- When the event happens during the session itself → event date = session date, no extra annotation needed

**Q5. Perceptibility**: Multimodal evidence must be directly perceivable by the model. Allowed attributes vary by modality:

| Modality | Allowed | Forbidden |
|----------|---------|-----------|
| **Image** | Object count, colors, scene type (indoor/outdoor), number of people, weather, object categories, spatial layout, text in image | Exact dimensions, camera model, file metadata |
| **Video** | All image attributes + action type, stage/state (half-finished/complete), scene transitions, number of distinct scenes | Exact duration in seconds, frame rate, resolution |
| **Audio (music)** | Instrument types/count, vocal presence and gender, energy/mood (intense/calm), tempo (fast/slow), genre feel | Exact BPM, decibel levels, bitrate, key signature |
| **Audio (speech)** | Language, speaker count, emotional tone, speaking pace (fast/slow) | Exact word count, duration in seconds |
| **Audio (sound)** | Sound source types (rain/traffic/birds), source count, indoor/outdoor environment | Exact decibel levels, frequency |

**Q6. Session-event order reversal (≥1 of 5)**: At least 1 question must have session chronological order opposite to event chronological order — a later session mentions an event that happened before an event mentioned in an earlier session. This tests whether the model confuses "when mentioned" with "when happened."

### Perceptual Branching

**P1. Mandatory perceptual branching**: Every question must include a **perceptual branching** mechanism — the multimodal content's perceivable attribute determines which temporal calculation path to follow. Without perceiving the multimodal content, there must be ≥2 possible answers.

**P2. Branch structure**: Each question requires:
- A **branching hop** (text type): A natural dialogue fragment that establishes a mapping between perceivable attributes and different time values. E.g., "the indoor shoot was five days ago, the outdoor one was eight days ago."
- A **multimodal hop**: Provides the perceivable fact (e.g., the photo is clearly an indoor scene) that selects the correct branch.
- The two branches must lead to **different final answers**. If both paths give the same answer, the branch is meaningless.

**P3. Branch naturalness**: The branching hop must read as natural dialogue, not a lookup table. The mapping should arise from the persona's activities.
- ✓ "I recorded the instrumental demo first, then added vocals three days later" (listener must determine: does this audio have vocals?)
- ✗ "If the audio has vocals the date is Jan 5, if no vocals the date is Jan 8" (artificial)

**P4. Branch count**: Exactly 2 branches per question. More adds complexity without testing temporal reasoning.

**P5. Distractor branch plausibility**: The wrong branch must be a plausible scenario — not obviously absurd. Both branches should involve the same persona activity domain.

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). Vary counts across the 5 questions.

**E2. Temporal safety**: All text hops must come from sessions with timestamps ≤ the multimodal hop's session timestamp. When multiple multimodal hops exist, check each independently. To provide temporal offsets related to multimodal content, use either:
- **Same-session text**: User provides time info in the same session as the multimodal upload (e.g., "this dinner was four days ago")
- **Pre-established rule**: An earlier session establishes a general pattern or scheduled event
- ✓ text S5 → image S7 → text S7 (same session as image)
- ✗ text S3 → image S5 → text S8 saying "that photo was from three days before..."

**E3. Multimodal content necessity**: The multimodal hop's perceivable content must be essential for resolving the perceptual branch. Verify: if you replace the multimodal content with a blank, the answer becomes ambiguous (≥2 possible answers). Session date alone is insufficient.

**E4. Hop necessity**: Remove any hop's temporal information → answer becomes undeterminable. State this in reasoning.

**E5. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. At most **1 text hop per question** may be a direct time/rule statement (`[explicit]`); all others must embed temporal info as incidental remarks (`[incidental]`). Tag each in reasoning.

**E6. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD). Only use sessions listed in Available Sessions. When using relative expressions, ensure they resolve to a single unambiguous date.

**E7. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type`, `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E8. Distribute multimodal positions**: The multimodal hop should appear at different positions across the 5 questions (beginning, middle, end).

**E9. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments to make it 4" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain (e.g., food photo for a gallery curator), abstract to domain-appropriate properties (color tone, texture, reflectivity) rather than referencing the source domain directly (seasoning, herbs).

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions (doing so would leak the branch answer).
- ✓ "the photo I shared the day of the birthday dinner"
- ✓ "the audio file I sent while testing boundary detection"
- ✗ "the photo showing an outdoor scene" (leaks indoor/outdoor branch)
- ✗ "the audio with guitar solo" (leaks instrument branch)

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.

5. **Temporal safety**: Every text hop's session timestamp ≤ each multimodal hop's session timestamp.
6. **Perceptual branching**: Each question has a branch where multimodal perception selects the temporal path. Without perceiving the content, ≥2 possible answers exist.
7. **Branch answer divergence**: The two branches lead to different final answers.
8. **Tight gaps**: Ordering → ≤2 days. Temporal Relationship → boundary ≤1 day from edge.
9. **Non-round answers**: Duration/Interval avoids 7, 14, 21, 30.
10. **Near-miss**: Recency/Extrema has ≥1 distractor within 1-2 days of boundary.
11. **Session-event reversal**: ≥1 of 5 questions has session order opposite to event order.
12. **Multimodal positions**: Distributed across questions (not always last).
13. **Necessity**: Each hop removal → answer undeterminable (stated in reasoning).
14. **Naturalism**: ≤1 `[explicit]` text hop per question. Others `[incidental]`.
15. **References**: Event-context only. No perceptual descriptions in questions (would leak branch). Unambiguous across sessions.
16. **Independent multimodal hops**: Each multimodal file is a separate hop with its own `mm_id` (string). No combined types like `image+audio`.
17. **Evidence quality**: Each text hop is self-contained (no missing subjects) and domain-coherent (no out-of-place terminology for the persona).
