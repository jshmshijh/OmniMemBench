You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, generate a question that requires identifying a value on a change timeline where that value can only be determined through multimodal perception. Target task type: **UPD (Knowledge Update)**.

Generate exactly 5 questions using the question session ID and its session summary to construct unambiguous references.

## SUBTYPES

| Subtype | Definition | Example Attributes | Construction | Common Errors |
|---------|-----------|-------------------|--------------|---------------|
| **State change** | Discrete state transitions | Job, location, equipment, tools | Build a change path (A→B or A→B→A') with fine-grained value similarity. Include reversion or lateral moves. | ✗ High-contrast values (acoustic guitar→synthesizer). ✗ Binary option space |
| **Numerical update** | Quantity changes | Pet count, instruments, publications | Increment/decrement with intermediate states. Include a near-miss distractor (considering but not purchasing). | ✗ Trivial +1 with no distractors. ✗ Value guessable from common knowledge |
| **Preference evolution** | Opinion/preference shifts | Favorite tool, preferred genre, workflow choice | Multi-step preference chain through adjacent alternatives. Include tried-then-abandoned steps. | ✗ Opposite-end swaps (folk→hip-hop). ✗ Predictable upgrade direction |

## RULES

### Question Design

**Q1. Ask for a value only obtainable from multimodal perception**: The question must target a specific value on the change timeline that can only be determined by perceiving the multimodal content (seeing the image/video, listening to the audio). The targeted value does not have to be the latest value — it can be any value on the chain, as long as the multimodal content is the sole source for that value.

**Q2. Fine-grained value similarity**: Old and new values must belong to the same fine-grained semantic category.
- ✓ Nike Vaporfly 2 → Nike Vaporfly 3 (same product line)
- ✓ post-rock → shoegaze (adjacent subgenres)
- ✗ acoustic guitar → synthesizer (different families)

**Q3. Answer = multimodal-dependent value**: The correct answer is the value that can only be established through multimodal perception. This may be the latest value, an earlier value, or an intermediate count — whichever the multimodal content uniquely provides.

**Q4. Perceptibility**: Multimodal evidence must be directly perceivable.
- ✓ Allowed: counts, presence/absence, colors, categories, visible objects, instrument types, emotional tone, music genre/style, spoken content, environmental sounds
- ✗ Forbidden: exact duration in seconds, BPM, frame rate, resolution, decibel levels

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). Vary counts across the 5 questions.

**E2. Temporal safety (UPD-specific)**: Because UPD tracks state changes over time, text hops MAY come from sessions after the multimodal hop's session. However, no text hop may describe the **perceptual content** of the multimodal item (what is visible/audible). Text hops may only reference the multimodal content by event context.
- ✓ text S14: "upgraded from my old pair — the new ones feel much better" (describes state change, not image content)
- ✗ text S14: "those blue and white Nike shoes in the photo I shared — I've switched from those"

**E3. Multimodal as timeline anchor**: The multimodal hop must represent a point on the change timeline (old state, intermediate state, or new state). Its perceptual content must be essential for establishing one value in the chain.

**E4. Multimodal irreplaceability**: No text hop may state what the multimodal content shows. The multimodal provides the perceptual fact; text hops provide state changes and context.

**E5. Multimodal information gap**: Removing all multimodal hops from the evidence chain must make the correct answer undeterminable from text alone. The multimodal content must be the **sole source** for the answer value or for information necessary to derive it. Specifically:
- Text hops may describe change actions ("switched", "added one more") but must NOT reveal the specific value that the multimodal content provides.
- If the answer is a count, text hops may describe increments/decrements but must not state the baseline count that only the multimodal reveals.
- If the answer is a specific item/state, text hops must not name it — they may only reference subsequent changes away from it.

**E6. Conflicting values**: At least 2 hops must contain different values for the same attribute.

**E7. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. At most **1 text hop per question** may be a direct state declaration (`[explicit]`); all others must embed state info as incidental remarks (`[incidental]`). Tag each in reasoning.

**E8. Session date vs. event date**: The `timestamp` field is always the session date. When events occurred at different times, describe the inferred event date in evidence text. The latest value is determined by inferred event dates.

**E9. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD). Only use sessions listed in Available Sessions.

**E10. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type`, `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E11. Distractor hop wording**: Use unambiguous language to distinguish considered-but-not-adopted from actually-adopted:
- **Considering**: "thinking about", "looking into", "might try"
- **Adopted**: "switched to", "decided on", "started using", "now using"
- **Tried-then-abandoned**: "tried X for a week but went back to", "experimented with X but didn't stick"

**E12. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain (e.g., food photo for a gallery curator), abstract to domain-appropriate properties (color tone, texture, reflectivity) rather than referencing the source domain directly (seasoning, herbs).

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the studio photo I shared during the gear discussion"
- ✗ "the photo showing four instruments on stands"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.

### Distribution Requirements (across all 5 questions)

**D1.** ≥2 must include **non-monotonic change** (A→B→A', tried-then-reverted)
**D2.** ≥2 must include a **distractor hop** (considered but not adopted)
**D3.** ≥2 must include **temporal mismatch** (event date ≠ session date)
**D4.** Multimodal positions must include at least: 1 beginning, 1 middle, 1 end
**D5.** ≥1 must have the latest value in a session that is NOT the chronologically latest session (latest session describes older state retrospectively)

## SELF-CHECK CHECKLIST

Before generating output, verify:

1. **Count**: Exactly 5 questions. ≥4 hops each (recommended 6).
2. **Subtypes**: Use different subtypes when possible.
3. **Value similarity**: Old and new values are from the same fine-grained category in every question.
4. **Non-monotonic change**: ≥2 of 5 have reversion or tried-then-reverted paths.
5. **Distractor hops**: ≥2 of 5 have a considered-but-not-adopted hop with unambiguous wording.
6. **Temporal mismatch**: ≥2 of 5 have event date ≠ session date.
7. **Multimodal positions**: At least 1 beginning, 1 middle, 1 end across 5 questions.
8. **Latest-not-in-latest-session**: ≥1 of 5 has the latest value in a non-final session.
9. **Temporal safety**: No text hop describes perceptual content of the multimodal item (what is visible/audible).
10. **Multimodal irreplaceability**: No text hop states what the multimodal content shows.
11. **Naturalism**: ≤1 `[explicit]` text hop per question. Others `[incidental]`.
12. **References**: Event-context only. Unambiguous across sessions.
13. **Answer**: Each answer is the value that can only be determined through multimodal perception.
14. **Independent multimodal hops**: Each multimodal file is a separate hop with its own `mm_id` (string). No combined types like `image+audio`.
15. **Evidence quality**: Each text hop is self-contained (no missing subjects) and domain-coherent (no out-of-place terminology for the persona).
16. **Masking test**: For each question, mentally remove all multimodal hops. If the correct answer can still be determined from text hops alone, the question is invalid — redesign so the multimodal content is the sole source for the answer value.
