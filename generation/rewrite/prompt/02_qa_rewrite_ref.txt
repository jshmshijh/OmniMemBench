You are generating multimodal QA data for a memory benchmark.

## TASK

Given multimodal content (captions), a user persona, and session context, create questions where the model must first perceive the multimodal content, then combine it with dialogue history, and ultimately discover that the information needed to fully answer is unavailable. Target task type: **REF (Answer Refusal)**.

**Core requirement**: Every REF question must make multimodal perception a necessary step in the reasoning path. If a question can be judged as unanswerable without engaging with the multimodal content, it is invalid. The model's reasoning must follow: perceive what the media shows/sounds like → search dialogue history for related context → discover that a critical piece of information is missing or uninferable.

Generate exactly 5 questions. Use the question session ID and its session summary to construct unambiguous references.

## SUBTYPES

| Subtype | Definition | Perception Role | short_answer | Construction |
|---------|-----------|----------------|-------------|-------------|
| **Never mentioned** | A specific detail was never stated in any session | Model perceives feature X from media, finds dialogue discussing X, but a critical instance-level detail about X was never provided | "Not mentioned" | Ask about an instance-level detail (a threshold, a recommendation, an exact criterion) that is closely tied to what is perceivable in the media. Dialogue must contain related discussion that creates temptation. |
| **Insufficient information** | Related information exists but is not enough to determine the answer | Model perceives feature X from media AND finds partial information about X in dialogue, but neither source alone nor both combined are sufficient | "Insufficient information" | Identify a gap where perception provides one part (e.g., "the pace sounds steady") and dialogue provides another part (e.g., "there's a minimum tempo"), but the two cannot be combined to reach a conclusion. |
| **Out of scope** | Requires information that inherently cannot be inferred from the content | Model perceives feature X, but the question asks about something beyond what any perception of this modality could reveal | "Cannot be inferred" | Ask about creator intent, events outside the content boundary, invisible identity, or prior external feedback — things that are fundamentally unobservable from the media itself. |

### Modality Perception Reference

Use this table as guidance for what models can and cannot extract from each modality. Questions should be designed around these boundaries.

| Modality | Can perceive | Cannot infer |
|----------|-------------|-------------|
| **Image** | Objects, colors, composition, spatial layout, text in image, emotional tone | Photographer identity, events before/after, creator intent, exact physical measurements, content outside the frame |
| **Video** | Actions, scene transitions, temporal order, object motion, expressions | Events before/after clip, off-camera activity, editor's intent, unshown context |
| **Audio (music)** | Melody, rhythm, instrumentation, dynamics, mood, key/mode | Composer intent, exact BPM, recording equipment, performer identity if unstated |
| **Audio (speech)** | Spoken words, tone, emotional state, language, speaker count | Speaker identity if unintroduced, unexpressed thoughts, referenced but undescribed events |
| **Audio (sound)** | Sound type, temporal pattern, relative loudness, co-occurring sounds | Exact source location, causal chain if not obvious, off-recording context |

## RULES

### Question Design

**Q1. Multimodal necessity**: Remove the multimodal content from the question context — if the question is still answerable as "unanswerable," the question is invalid. The multimodal content must provide information that is essential to understanding what is being asked or why it cannot be answered.

**Q2. Difficulty gate**: Every REF question must pass: *Would a strong model be tempted to answer using what it perceived from the media, world knowledge, or related dialogue context, rather than refusing?* If not, redesign.

**Q3. Instance-level gap**: The missing piece must be instance-level information only the user could know (a specific threshold, a personal recommendation, an exact criterion). General domain expertise must NOT be sufficient to fill the gap.

**Q4. Multi-step discovery**: Simple one-hop absence ("X is not mentioned") is forbidden. The question must require at least two reasoning steps before the gap is discovered.

**Q5. Dialogue-history temptation (≥2 of 5)**: At least 2 questions must derive temptation from related but insufficient information present in conversation history — the dialogue contains discussion of the relevant topic, making the model believe it has enough context, but a critical detail is missing.

**Q6. Perceptibility**: When describing what IS available, use perceivable attributes only.
- ✓ Allowed: counts, presence/absence, colors, actions, relative comparisons, emotional tone
- ✗ Forbidden: exact duration in seconds, BPM, frame rate, resolution, decibel levels

### Evidence Chain

**E1. Hop count**: ≥4 hops per question (recommended 6). The hops provide relevant context that looks sufficient while revealing what IS available vs. what is missing.

**E2. Multimodal hop evidence format**: Each multimodal hop's `evidence` field must describe (a) what is perceivable from this content, and (b) what specific information remains unavailable despite this perception. Both parts must be present.

**E3. Temporal safety**: All text hops must come from sessions with timestamps ≤ the multimodal hop's session timestamp. When multiple multimodal hops exist, check each independently.
- ✓ text S3 (Jan 3) → image S5 (Jan 5)
- ✗ text S7 discussing what S5's image shows → image S5

**E4. Evidence naturalism**: Write evidence as naturalistic dialogue fragments. Tag each text hop as `[explicit]` or `[incidental]` in reasoning. At most **1 text hop per question** may be `[explicit]`.

**E5. Session grounding**: Each hop must include `session_id` and `timestamp` (YYYY-MM-DD). Only use sessions listed in Available Sessions.

**E6. Independent multimodal hops**: Each multimodal file is an independent hop with its own `mm_id` (string). Do NOT combine multiple multimodal files into a single hop. Each multimodal hop has its own `type`, `session_id`, `timestamp`, `evidence`, and `mm_id`.

**E7. Evidence quality**: 
- **Self-contained**: Each text hop must name its subject explicitly. "adding three more to make it 4" → bad (what?). "adding three more stringed instruments to make it 4" → good.
- **Domain-coherent**: Rules/criteria in evidence must sound natural for the persona. If the multimodal content is from a mismatched domain (e.g., food photo for a gallery curator), abstract to domain-appropriate properties (color tone, texture, reflectivity) rather than referencing the source domain directly (seasoning, herbs).

### Reference Style

**R1. Event context only**: Reference multimodal content by occasion, timing, or purpose — never by perceptual descriptions.
- ✓ "the skull X-ray I shared during the ER module review"
- ✗ "the X-ray showing a fracture line"

**R2. Unambiguous identification**: References must uniquely identify the target session among all available sessions.

### Distinction from ADV

- **REF**: No sufficient information exists to answer the question.
- **ADV**: Relevant information exists and contradicts a false claim.

## SELF-CHECK CHECKLIST

Before generating output, verify:

1. **Count**: Exactly 5 questions.
2. **Subtypes**: Use different subtypes across questions when possible.
3. **Multimodal necessity (Q1)**: For each question, confirm: if the multimodal content were removed, could the model still determine the question is unanswerable? If yes, redesign.
4. **Hops**: ≥4 per question (recommended 6). Each multimodal file is a separate hop.
5. **Multimodal hop evidence**: Each multimodal hop describes both what is perceivable and what remains unavailable.
6. **Temporal safety**: Every text hop's session timestamp ≤ each multimodal hop's session timestamp.
7. **Difficulty**: Every question would tempt a strong model to answer rather than refuse.
8. **Instance-level gap**: The missing piece cannot be filled by domain knowledge alone.
9. **Multi-step**: Gap requires ≥2 reasoning steps to discover.
10. **Dialogue temptation**: ≥2 of 5 questions derive temptation from conversation history.
11. **Naturalism**: Evidence is dialogue fragments. Text hops tagged `[explicit]` or `[incidental]`. ≤1 `[explicit]` per question.
12. **References**: Event-context only. Unambiguous across sessions.
13. **short_answer matches subtype**: "Not mentioned" / "Insufficient information" / "Cannot be inferred".
14. **Not ADV**: Questions ask for absent info, not contradictions with false claims.
15. **Independent multimodal hops**: Each multimodal file is a separate hop with its own `mm_id` (string).
16. **Evidence quality**: Each text hop is self-contained and domain-coherent.
